# Code Review Configuration

## Always Ignore

The following files and directories are vendored third-party code, auto-generated output, or binary resource data. They should be **skipped entirely** during review. **DO NOT** even read them and waste any tokens. **DO NOT** use these files when determining how many REVIEW agents to launch. It is a **CRITICAL** cost containment measure. **NEVER** include in any PR analysis.

---

### Vendored Third-Party Dependencies (`include/`)

All files in the `include/` directory are vendored third-party libraries and should be skipped entirely during review.

- `include/catch2/` — Catch2 v2.13.8 unit testing framework (Boost License). Header-only, not cisTEM code.
- `include/gemmi/` — GEMMI macromolecular crystallography library (Mozilla Public License v2.0). Includes its own `third_party/` subdirectory containing TAO PEGTL, fast_float, pocketfft, sajson, stb_sprintf, and tinydir. All vendored, none written by cisTEM developers.
- `include/ieee-754-half/` — IEEE 754 half-precision floating point library (MIT License). Header-only.
- `include/libtorch/` — LibTorch helper header.

**DO NOT** comment on code style, potential bugs, or improvements in any file under `include/`. These are upstream dependencies we do not maintain.

---

### Vendored Code in `src/core/`

- `src/core/sqlite/` — Complete SQLite3 amalgamation distribution (~7.2 MB). This is the official SQLite3 source release embedded verbatim. **DO NOT** review `sqlite3.c`, `sqlite3.h`, `sqlite3ext.h`, `shell.c`, or anything in `old_version/`. These files are public domain upstream code and are never modified by cisTEM developers.
- `src/core/tiff/` — TIFF library headers (`tiff.h`, `tiffio.h`, `tiffconf.h`, `tiffvers.h`). Vendored from libtiff, not cisTEM code.

---

### wxFormBuilder Auto-Generated GUI Code

All files matching the following patterns are **auto-generated** by wxFormBuilder from `.fbp` design files. They contain the explicit header comment `PLEASE DO *NOT* EDIT THIS FILE!` and must be skipped entirely:

- `src/gui/ProjectX_gui_*.h` — 14 auto-generated header files
- `src/gui/ProjectX_gui_*.cpp` — 14 auto-generated implementation files
- `src/gui/wxformbuilder/*.fbp` — wxFormBuilder project files (XML design data, not human-authored C++)

These files are regenerated from the `.fbp` sources. Any review comments on them are wasted effort. **DO NOT** flag style issues, suggest refactors, or comment on patterns in these files.

---

### Icon Resource Files (`src/gui/icons/`)

All files in `src/gui/icons/` are binary resources and should be skipped entirely:

- `src/gui/icons/*.cpp` — 75+ files containing hex-encoded PNG binary data converted to C++ arrays by the `bin2c` utility. These are machine-generated data blobs with zero semantic content to review.
- `src/gui/icons/*.png` — Binary PNG image files.
- `src/gui/icons/bin2c` — Icon conversion utility.
- `src/gui/icons/convert_png_to_cpp.b` — Conversion build script.

**DO NOT** read, analyze, or comment on any file in `src/gui/icons/`. They are binary data, not logic.

---

### Autotools Generated Build Files

The following top-level files are generated by GNU Autotools (`autoconf`, `automake`, `libtool`) from `configure.ac` and `Makefile.am`. They are regenerated by running `./regenerate_project.b` and should never be reviewed:

- `configure` — 22,000+ line shell script generated by Autoconf
- `aclocal.m4` — Generated macro definitions
- `Makefile.in` — Generated Makefile template (also `src/Makefile.in`)
- `config.guess` — Platform detection script (GNU upstream)
- `config.sub` — Platform normalization script (GNU upstream)
- `install-sh` — Installation script (GNU upstream)
- `compile` — Compilation wrapper (GNU upstream)
- `missing` — Missing tool wrapper (GNU upstream)
- `depcomp` — Dependency tracking script (GNU upstream)
- `ltmain.sh` — Libtool main script (GNU upstream)
- `cistem_config.in` — Configuration header template generated by autoheader

**DO NOT** review these files. They are standard GNU Autotools boilerplate regenerated from `configure.ac`.

---

### ctffind_standalone (External Subproject)

The entire `ctffind_standalone/` directory is a separate external software distribution (CTFFIND, GNU AGPL v3) with its own independent build system. It is not cisTEM application code.

**DO NOT** review any file in `ctffind_standalone/`. This includes its `configure`, `configure.ac`, `Makefile.am`, `Makefile.in`, `aclocal.m4`, `CMakeLists.txt`, and all other contents.

---

### Build Directories and Caches

- `build/` — Compiled object files, libraries, and executables. Build artifacts only.
- `autom4te.cache/` — Autotools internal cache directory.

These directories contain only build output and should never appear in a PR diff, but if they do, skip them entirely.
